# Decision Filter

Use this filter before any product, sales, or implementation decision.

If a request fails the filter, do not build it. Escalate to the founder.

## Who decides

The founder owns customer discovery, sales, product direction, customer relationships, positioning, and business strategy.

Cursor is an implementation tool. It must not make major product or business decisions autonomously.

## Required questions

Work proceeds only if the answer is yes, or the founder has explicitly approved an exception.

1. Does this improve the loop: inquiry → response → qualification → appointment → deposit → show-up?
2. Is this in the current MVP, or a repeated need confirmed in real clinics?
3. Does this serve premium private dental clinics in Casablanca and Marrakech?
4. Would we still do this if we were not allowed to mention AI?
5. Can we measure the result in conversion or revenue terms?

If the work exists mainly to look like a complete clinic platform or an AI demo, stop.

## Automatic no

Do not do these unless the founder later changes the blueprint:

- voice AI
- medical records
- CNSS / CNOPS
- odontogram
- accounting, payroll, inventory
- full clinic management
- complex CRM
- ERP
- multi-country functionality
- multi-vertical functionality
- autonomous AI agents
- unnecessary AI features
- advanced reporting
- billing infrastructure unless required by the MVP
- generic chatbot positioning (“AI receptionist”, “AI employee”)
- mass Instagram DMs as the primary acquisition strategy
- targeting every dentist
- building from assumption instead of evidence

## Scope tests

| If the request is… | Then… |
| --- | --- |
| Extra MVP feature “while we’re here” | Refuse. Specify or iterate later with evidence. |
| Another vertical (aesthetic, etc.) | Refuse for now. Record only. |
| Another country | Refuse for now. |
| PMS / records / billing ops | Refuse. Wrong category. |
| More AI autonomy | Refuse. Human takeover first. |
| Pretty prototype without a real clinic | Refuse. Working product over prototypes. |
| Optimization of AI message count | Refuse. Wrong metric. |

## Pricing and commercial tests

- Price against recovered-patient value, not cheap PMS comps.
- Do not invent tiers, add-ons, or public prices.
- Setup 8,000–15,000 MAD and monthly 3,500–8,000 MAD are targets, not fixed SKUs.

## Metric test

Prefer work that can move:

**Deposited consultations generated through Selaren**

Supporting: response time, qualified inquiry rate, booking rate, deposit rate, show-up rate, recovered inquiries, estimated revenue generated.

## Principle test

The decision must survive `blueprint/Company/Principles.md`, especially:

- revenue over features
- customer evidence over assumptions
- never become a generic AI wrapper
- never become a clinic PMS
- stay obsessed with the inquiry-to-appointment loop
